# Review team changes
Read ../../references/operating-contract.md first.

1. Resolve the space and requested proposal(s). Read exact deltas, cited sources, current affected pages, Rules, and recorded reviewer/approval information. Present a concise assessment: evidence strength, contradictions, human text affected, and outstanding decisions.
2. Resolve whether the user is requesting assessment, revision, rejection, or application. Assessment alone is read-only. Do not manufacture approval or infer authority from write access. Follow configured reviewer authority; if it cannot be verified for a gated change, keep a fully drafted proposal pending.
3. On authorized approval/application, compare current target versions with proposal base versions. Rebase non-overlapping changes while preserving human edits. If meaning or evidence changed, return an updated proposal for review rather than applying stale approval to new content.
4. Apply guarded changes per page, recording progress under the operation ID. Mark the proposal applied only after every intended change is verified; partial failure stays partial with completed/pending steps. Update Index and Activity. Record actual approver identity only when verified and use explicit evidence of their approval.
5. Preserve rejected/superseded proposals for audit. Never delete dissent or transfer page ownership as a side effect. Return applied page links and unresolved decisions.
